# Expert-labelled extension study — pre-registered protocol (Access-2026-46118 revision)

Committed before (a) the external expert sees any case, (b) any AAF, rule or LLM configuration is run on the new
cases. Nothing in this folder has been executed on the new cases at the time of this commit.

## Purpose
Answer three open reviewer concerns with one study:
1. **Oracle independence (R6-4, R1-4):** an external expert, not an author, labels admissible actions blind.
2. **Sample size (R1-3, R3-2):** 48 new cases, frozen before labelling and before any run.
3. **Where the LLM adds unique value (R4-1, R5-1, R6-1):** a stratum whose decisive information is not flagged as
   missing, so a field-name fetch rule cannot know what to fetch.

## Cases (`cases_new_v1.yaml`, generated by `make_cases.py`)
- **Standard (24):** 6 CLEAR, 6 AMBIGUOUS, 6 INCOMPLETE (decisive field explicitly marked missing), 6 MISLEADING,
  same format as the original 32 + 16 cases.
- **UNMARKED (24):** the decisive information is
  - *absent* without a missing flag (NV-U01–U06, U22; 7 cases),
  - *stale* (present with `status: stale` and an age; NV-U07–U12, U23; 7 cases), or
  - in *another domain's* tool (NV-U13–U18; 6 cases);
  - plus 4 *controls* where the relevant tool confirms the action already indicated (NV-U19, U20, U21, U24).
  Each UNMARKED case lists 3–4 approved read-only tools, one of which returns the decisive evidence.
- `author_labels.yaml` holds the authors' proposed admissible actions, sealed in this commit. It is **not** the
  primary answer key for the new cases.

## Expert labelling (blind)
- One external practitioner with SRE/DevOps governance experience, not an author and not involved in AAF's design.
- Labels all 96 cases (48 original + 48 new) in random order (seed 20261022) without seeing strata, case focus, the
  author oracle, AAF's rules or any configuration's output.
- For each case the expert sees the evidence available at decision time and, where applicable, what an up-to-date
  check would show (the case's tool result), i.e. the full situation. The expert marks every acceptable action
  (one or more of the 8 actions), the single best action, a confidence (1–3), and may mark "cannot decide".
- Labels are stored with timestamps and exported to `expert_labels.json` before any run on the new cases.

**Answer keys.** New cases: the expert's acceptable set (primary). Original 48 cases: both keys are reported (author
oracle as in the manuscript; expert key as the independent check). Cases marked "cannot decide" are excluded from
expert-key scoring and reported.

## Configurations (frozen code; no tuning on the new cases)
| Arm | LLM | Description |
| --- | --- | --- |
| DET | no | deterministic AAF (`hybrid.deterministic_assessment`) |
| AF-M | no | auto-fetch: for each field marked *missing*, call its mapped tool (`revision_2026/autofetch_baseline.FIELD_TO_TOOL`) |
| AF-MS | no | as AF-M, also re-fetching fields marked *stale* (a stronger rule baseline) |
| FETCH-ALL | no | call every available tool once, then decide deterministically (upper-bound rule; maximal tool use) |
| HY | yes | Hybrid AAF, frozen `hybrid.run_hybrid`, reasoning none; 3 runs |
| AO | yes | Agentic-only original, 1 run |
| B3 | no new calls | always-on agents + deterministic authority, from AO tool traces |
| B6 | yes | enhanced Agentic-only (reasoning medium + governance rules), 1 run |

Tool semantics are unchanged from the original study: a requested tool returns the case's recorded result only if it
is the case's evidence-bearing tool; other tools return "no additional evidence".

Budget caps: 1,500 LLM calls and 1.2M tokens in total; a probe call first; the run stops on any account error.

## Analyses (pre-specified)
- **H1 Oracle agreement (96 cases):** share of cases where the expert's best action is in the author set; mean
  Jaccard overlap of the two acceptable sets; Cohen's kappa between the expert's best action and the author's first
  listed action. Reported overall and for original vs new cases. No pass/fail threshold.
- **H2 Original results under the expert key (48 cases):** majority-of-runs correctness of every original
  configuration (DET, auto-fetch, HY, AO, B3, B6, prompt rewordings) re-scored on expert labels; paired exact McNemar
  HY vs DET and HY vs B6.
- **H3 LLM unique value (UNMARKED decisive cases, n = 20; controls reported separately):** HY (majority of 3 runs)
  vs AF-MS and HY vs AF-M, paired exact McNemar, Holm-corrected over these two; HY vs FETCH-ALL reported with
  tool calls per case. HY's trigger rate on UNMARKED cases is reported (the trigger is frozen and may not fire).
- **H4 Standard new cases (24) and pooled standard cases (72):** HY vs DET, HY vs B6, HY vs AO.
- Stability: cases with the same HY action in all 3 runs. Cost: LLM calls, tokens, tool calls per case.

## What would count against AAF
H3 showing HY no better than AF-MS (the LLM adds nothing a stale-aware rule cannot); H1 showing low agreement
(the author oracle does not reflect practitioner judgement); H2 changing the ranking of configurations. All outcomes
will be reported.
