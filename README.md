# AgileOps Agent Framework (AAF)

Reproducibility repository for the manuscript:

**Cross-Domain Evidence Integration for Project Governance in Agile–DevOps: An Explainable Multi-Agent Decision-Support Framework**

AAF is a deterministic, evidence-driven multi-agent decision-support framework for integrating DevOps, Site Reliability Engineering (SRE), FinOps, and DevSecOps evidence into bounded project-governance recommendations. An optional LLM layer can interpret bounded PM questions and verbalize the structured decision; it does not change the selected governance action or create operational evidence.

> **Looking for the experiment-to-data-to-results map? See [paper_results/README.md](paper_results/README.md).**

## Quick start

```bash
git clone https://github.com/Ksuresh/AgileOps-Agentic-Framework.git
cd AgileOps-Agentic-Framework
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\\Scripts\\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
export PYTHONPATH="$PWD"         # PowerShell: $env:PYTHONPATH=(Get-Location)
python -m pytest -q
```

The runtime benchmark studies additionally require Docker/Docker Compose (Sock Shop) or Docker + kubectl + kind (Online Boutique).

## Evidence used in the paper

This work does **not** depend on one conventional ML dataset.

- **Controlled evidence:** deterministic scenarios generated by `scenario_generator/` using frozen configurations/seeds and evaluated against pre-specified oracles in `benchmark/`.
- **Sock Shop runtime evidence:** operational evidence collected from the open-source Sock Shop benchmark after pre-specified interventions in `runtime_validation/interventions*.yaml`.
- **Google Online Boutique runtime evidence:** Kubernetes and HTTP evidence collected from a pinned Online Boutique revision after pre-specified interventions in `runtime_validation/interventions_online_boutique.yaml`.
- **Learned-baseline data:** 120 calibration instances generated from 30 controlled templates using seeds 42–45; the frozen held-out feature snapshot is `experiments/learned_baseline_hrt_template_features.csv`.

Sock Shop and Online Boutique are open-source benchmark workloads; they are **not customer-production datasets**.

## Results policy

Generated runtime evidence and rerun outputs are not committed as if they were immutable datasets. They are produced by the documented commands/workflows and are preserved as GitHub Actions artifacts. `paper_results/README.md` provides the canonical map from each manuscript experiment to its evidence definition, execution command, and generated result location.

This separation prevents a fresh rerun from being confused with the historical frozen execution used during manuscript development.

## Runtime validation

### Sock Shop

`runtime_validation/RUNTIME_VALIDATION_DESIGN.md` defines the protocol. Raw artifacts are collected before AAF inference and converted to structured evidence by `runtime_validation/evidence_adapter.py`. The prospective HRT-32–HRT-39 experiment is executable through `.github/workflows/aaf-v2-prospective-runtime.yml`.

### Google Online Boutique

The Online Boutique reproduction files are consolidated on `main`: `runtime_validation/interventions_online_boutique.yaml`, `runtime_validation/run_online_boutique_case.py`, `runtime_validation/evaluate_online_boutique.py`, and `.github/workflows/runtime-online-boutique.yml`. The workflow pins the upstream benchmark revision, creates a kind cluster, executes OB-01–OB-08, evaluates AAF and baselines, and uploads evidence/results.

### Learned baselines

`experiments/run_learned_baselines.py` and `experiments/learned_baseline_hrt_template_features.csv` are on `main`. The script trains fixed logistic-regression and shallow decision-tree baselines only on generated controlled/calibration scenarios and evaluates once on the frozen HRT feature snapshot. `.github/workflows/learned-baselines.yml` provides the automated run.

## Reproducibility principles

- Intervention definitions and admissible governance-action sets are fixed before runtime inference.
- AAF does not receive the intervention/oracle label as input.
- Raw runtime artifacts are preserved before evidence transformation.
- Benchmark source revisions are pinned for confirmatory/prospective runs.
- Runtime resource scaling is represented as a resource-footprint proxy when monetary cloud-cost evidence is unavailable.
- Historical experiment branches are retained only for provenance; reproduction prerequisites are consolidated on `main`.

## Historical provenance

The former synthetic-only `main` is preserved at `archive/pre-paper-2026-main`. Historical experiment branches are retained to preserve exact development/execution states, but a new reproducer should start from current `main`.
