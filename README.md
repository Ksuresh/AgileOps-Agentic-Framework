# AgileOps Agent Framework (AAF)

Reproducibility repository for the manuscript:

**Cross-Domain Evidence Integration for Project Governance in Agile–DevOps: An Explainable Multi-Agent Decision-Support Framework**

AAF is a deterministic, evidence-driven multi-agent decision-support framework for integrating DevOps, Site Reliability Engineering (SRE), FinOps, and DevSecOps evidence into bounded project-governance recommendations. An optional LLM layer can interpret bounded PM questions and verbalize the structured decision; it does not change the selected governance action or create operational evidence.

> **Reproducing the paper? Start with [REPRODUCE_CURRENT_PAPER.md](REPRODUCE_CURRENT_PAPER.md).** It maps every reported experiment to its code, evidence, pinned benchmark revision, workflow, and command.

## Quick start

For the deterministic experiments and unit/regression tests:

```bash
git clone https://github.com/Ksuresh/AgileOps-Agentic-Framework.git
cd AgileOps-Agentic-Framework
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\\Scripts\\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
export PYTHONPATH="$PWD"         # PowerShell: $env:PYTHONPATH=(Get-Location)
python -m pytest -q
```

The runtime benchmark studies additionally require Docker/Docker Compose (Sock Shop) or Docker + kubectl + kind (Online Boutique).

## Evidence used in the paper

This work does **not** depend on one conventional ML dataset.

- **Controlled evidence:** deterministic scenarios generated by `scenario_generator/` using frozen configurations/seeds.
- **Sock Shop runtime evidence:** raw operational evidence collected from the open-source Sock Shop microservice application after pre-specified interventions.
- **Google Online Boutique runtime evidence:** Kubernetes and HTTP evidence collected from a pinned Online Boutique revision after pre-specified interventions.
- **Learned-baseline calibration data:** 120 controlled instances generated from 30 templates using seeds 42, 43, 44, and 45. Held-out HRT templates are not used for fitting.

Sock Shop and Online Boutique are realistic open-source benchmark workloads; they are **not customer-production datasets**.

## Runtime validation

### Sock Shop

`runtime_validation/RUNTIME_VALIDATION_DESIGN.md` defines the runtime protocol. Intervention manifests and executable runners are under `runtime_validation/`. Raw artifacts are collected before AAF inference and then converted to structured evidence by `runtime_validation/evidence_adapter.py`.

The prospective finalized-arbitration experiment HRT-32–HRT-39 is executable through `.github/workflows/aaf-v2-prospective-runtime.yml`, which pins the Sock Shop source revision and preserves the complete result/evidence artifact.

### Google Online Boutique

The exact frozen Online Boutique replication remains on `experiment/aaf-second-benchmark-online-boutique`. Its workflow `.github/workflows/runtime-online-boutique.yml` pins the upstream benchmark revision, creates a kind cluster, executes OB-01–OB-08, evaluates AAF and baselines, and uploads the evidence/results.

### Learned baselines

The exact learned-baseline experiment remains on `experiment/aaf-learned-baselines`. `experiments/run_learned_baselines.py` trains fixed logistic-regression and shallow decision-tree baselines only on controlled/calibration scenarios and evaluates once on the frozen HRT feature snapshot.

## Reproducibility principles

- Intervention definitions and admissible governance-action sets are fixed before runtime inference.
- AAF does not receive the intervention/oracle label as input.
- Raw runtime artifacts are preserved before evidence transformation.
- Benchmark source revisions are pinned for confirmatory/prospective runs.
- Runtime resource scaling is represented as a resource-footprint proxy when monetary cloud-cost evidence is unavailable.
- Historical experiment branches are retained to preserve the exact code state used for each frozen study.
