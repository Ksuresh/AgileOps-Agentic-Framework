# Reproducing the IEEE Access experiments

This is the entry point for reproducing the experiments reported in the current AAF manuscript.

## Evidence used

AAF does not depend on one conventional ML dataset. The paper uses:

1. **Controlled scenario evidence** generated deterministically by `scenario_generator/`.
2. **Sock Shop runtime evidence** produced by pre-specified interventions against the open-source Sock Shop benchmark.
3. **Google Online Boutique runtime evidence** produced by pre-specified interventions against a pinned open-source Online Boutique revision.
4. **Frozen HRT feature evidence** for the independent learned-baseline comparison.

The learned baselines are fitted only on 120 controlled/calibration instances: 30 templates generated under seeds 42, 43, 44 and 45. HRT templates are not used for fitting or hyperparameter selection.

## 1. Checkout and test

```bash
git clone https://github.com/Ksuresh/AgileOps-Agentic-Framework.git
cd AgileOps-Agentic-Framework
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
export PYTHONPATH="$PWD"         # PowerShell: $env:PYTHONPATH=(Get-Location)
python -m pytest -q
```

Python 3.11 is the reference version used by the GitHub Actions workflows.

## 2. Controlled experiments

```bash
python evaluation/run_oracle_benchmark.py
python evaluation/run_revised_comparison.py
python evaluation/run_sensitivity_analysis.py
python experiments/run_cross_domain_heldout.py
python experiments/parameter_sensitivity_2026.py
```

The generator is deterministic for fixed seeds/configuration. Experiment definitions and protocol notes are under `experiments/`.

## 3. Sock Shop held-out runtime validation

Requirements: Docker Engine, Docker Compose v2 and Git.

Definitions and evidence-handling code are under `runtime_validation/`, including:

- `interventions.yaml`
- `interventions_batch3.yaml`
- `interventions_expanded_heldout.yaml`
- `interventions_extended_validation.yaml`
- `evidence_adapter.py`

The GitHub Actions workflows under `.github/workflows/runtime-*.yml` provide executable reference procedures. Raw evidence generated by a run is written under `runtime_validation/artifacts/<HRT-ID>/` and evaluated by the corresponding `evaluate_*runtime.py` script.

Example after starting Sock Shop and setting `SOCK_COMPOSE`:

```bash
python runtime_validation/run_runtime_case.py HRT-01 --repetition 1 --compose-file "$SOCK_COMPOSE" --settle-seconds 10 --execute
python runtime_validation/evaluate_heldout_runtime.py --cases HRT-01 --repetitions 1 --out results_heldout_runtime
```

## 5. Google Online Boutique benchmark

The complete reproduction code is now available directly on `main`.

Requirements: Docker, kubectl, kind and Git.

Pinned Online Boutique revision:

`b9a978db9e01f4ad3dca9494a22cb9edc17548fe`

Files:

- `runtime_validation/interventions_online_boutique.yaml`
- `runtime_validation/run_online_boutique_case.py`
- `runtime_validation/evaluate_online_boutique.py`
- `.github/workflows/runtime-online-boutique.yml`

The easiest exact reproduction is to run the **Online Boutique Frozen Second Benchmark** workflow manually in GitHub Actions. It creates a kind cluster, deploys the pinned benchmark revision, executes OB-01 through OB-08, evaluates the outputs and uploads the evidence bundle.

The same runner can be invoked locally after deploying the pinned Online Boutique revision and port-forwarding the frontend to `127.0.0.1:8080`:

```bash
for i in 01 02 03 04 05 06 07 08; do
  python runtime_validation/run_online_boutique_case.py "OB-$i"
done
python runtime_validation/evaluate_online_boutique.py
```

## 6. Learned baselines

The complete learned-baseline experiment is also available directly on `main`:

- `experiments/run_learned_baselines.py`
- `experiments/learned_baseline_hrt_template_features.csv`
- `.github/workflows/learned-baselines.yml`

Run locally with:

```bash
python experiments/run_learned_baselines.py
```

This generates 120 controlled/calibration training instances using seeds 42-45, fits the fixed logistic-regression and shallow decision-tree baselines, and evaluates them on the frozen HRT-01..HRT-13 feature snapshot. The held-out feature snapshot is never used for fitting, feature selection or hyperparameter tuning.

## Interpretation boundary

Sock Shop and Online Boutique are open-source benchmark applications, not customer-production datasets. Their evidence is generated by controlled, pre-specified interventions. Replica expansion is used only as a resource-footprint proxy where monetary cloud-billing evidence is unavailable; it must not be interpreted as observed cloud cost.

## Provenance

`main` is the unified reproducibility branch for the current manuscript. Historical frozen experiment branches remain in the repository to preserve the exact states in which individual studies were originally executed. The previous pre-paper main branch is preserved as `archive/pre-paper-2026-main`.

For verification, use the pinned upstream benchmark commits and frozen manifests documented above rather than the latest upstream benchmark revisions.
