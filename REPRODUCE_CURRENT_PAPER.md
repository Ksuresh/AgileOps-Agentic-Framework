# Reproducing the IEEE Access experiments

This document is the entry point for reproducing the experiments reported in the current AAF manuscript.

## What counts as data

AAF does not use one conventional ML training dataset. The evidence comes from three sources:

1. **Controlled scenario data** generated deterministically by the repository scenario generator.
2. **Sock Shop runtime evidence** collected after pre-specified interventions against the open-source Sock Shop microservice benchmark.
3. **Google Online Boutique runtime evidence** collected after pre-specified interventions against the open-source Online Boutique benchmark.

The learned comparison baselines use 120 controlled/calibration instances (30 templates x seeds 42, 43, 44, 45) for fitting. Held-out HRT templates are not used for fitting.

## Prerequisites

For deterministic/local experiments:
- Python 3.11+

For Sock Shop runtime experiments:
- Docker Engine
- Docker Compose v2
- Git

For Online Boutique runtime experiments:
- Docker
- kubectl
- kind v0.24.0 or compatible
- Git

## Checkout and Python setup

```bash
git clone https://github.com/Ksuresh/AgileOps-Agentic-Framework.git
cd AgileOps-Agentic-Framework
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\\Scripts\\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
export PYTHONPATH="$PWD"         # PowerShell: $env:PYTHONPATH=(Get-Location)
python -m pytest -q
```

The test suite should pass before reproducing results.

## Study 1 - controlled evidence experiments

The controlled scenarios are generated by `scenario_generator/`. The post-review evaluation scripts are under `evaluation/` and `experiments/`.

Useful entry points:

```bash
python evaluation/run_oracle_benchmark.py
python evaluation/run_revised_comparison.py
python evaluation/run_sensitivity_analysis.py
python experiments/run_cross_domain_heldout.py
python experiments/parameter_sensitivity_2026.py
```

Each script writes its result files to its declared output directory. Scenario generation is deterministic for fixed seeds/configuration.

## Study 2 - Sock Shop held-out runtime validation

Design and frozen intervention definitions:

- `runtime_validation/RUNTIME_VALIDATION_DESIGN.md`
- `runtime_validation/interventions.yaml`
- `runtime_validation/interventions_batch3.yaml`
- `runtime_validation/interventions_expanded_heldout.yaml`
- `runtime_validation/interventions_extended_validation.yaml`

Runtime evidence is collected from a real execution of the open-source Sock Shop benchmark. Raw evidence is preserved under `runtime_validation/artifacts/<HRT-ID>/` during a run and transformed by `runtime_validation/evidence_adapter.py`.

The simplest exact reproduction is the GitHub Actions workflow `.github/workflows/runtime-heldout.yml`. Its steps are intentionally shell commands that can also be executed locally: clone Sock Shop, start it with Docker Compose, run each intervention, evaluate the preserved artifacts, and restore the workload.

For example, after starting Sock Shop and setting `SOCK_COMPOSE` to its Docker Compose file:

```bash
python runtime_validation/run_runtime_case.py HRT-01 --repetition 1 --compose-file "$SOCK_COMPOSE" --settle-seconds 10 --execute
python runtime_validation/evaluate_heldout_runtime.py --cases HRT-01 --repetitions 1 --out results_heldout_runtime
```

For the expanded HRT suites use the matching `run_*case.py` and `evaluate_*runtime.py` files in `runtime_validation/`.

## Study 3 - prospective finalized-arbitration validation (HRT-32 to HRT-39)

The frozen prospective manifest is:

`runtime_validation/interventions_v2_prospective.yaml`

The exact reproducible workflow is:

`.github/workflows/aaf-v2-prospective-runtime.yml`

It pins Sock Shop to commit:

`9dff06fae4981921caec6a62393a6ebfce4b3e3f`

The workflow records the frozen policy/manifest hashes, runs HRT-32 through HRT-39 once each, evaluates the initial and finalized arbitration policies, records Docker versions, and uploads the complete evidence/result artifact.

Local evaluation entry points are:

```bash
python runtime_validation/run_v2_prospective_case.py HRT-32 --repetition 1 --compose-file "$SOCK_COMPOSE"
python runtime_validation/evaluate_v2_prospective_runtime.py
```

## Study 4 - Google Online Boutique replication

The Online Boutique study was executed from the frozen historical branch:

`experiment/aaf-second-benchmark-online-boutique`

The exact executable workflow is:

`.github/workflows/runtime-online-boutique.yml`

on that branch. It pins Online Boutique to commit:

`b9a978db9e01f4ad3dca9494a22cb9edc17548fe`

To reproduce exactly:

```bash
git checkout experiment/aaf-second-benchmark-online-boutique
python -m pytest -q
```

Then either dispatch `runtime-online-boutique.yml` in GitHub Actions or follow its commands locally. The workflow installs kind, creates a Kubernetes cluster, deploys the pinned Online Boutique revision, executes OB-01 through OB-08, evaluates the results, records environment metadata, and preserves the evidence artifact.

Key files:
- `runtime_validation/interventions_online_boutique.yaml`
- `runtime_validation/run_online_boutique_case.py`
- `runtime_validation/evaluate_online_boutique.py`

## Study 5 - learned baselines

The learned-baseline study is frozen on:

`experiment/aaf-learned-baselines`

Reproduce it with:

```bash
git checkout experiment/aaf-learned-baselines
pip install -r requirements.txt
pip install scikit-learn
python experiments/run_learned_baselines.py
```

The script generates the 120 training/calibration instances from the controlled generator using seeds 42-45, fits fixed logistic-regression and shallow decision-tree baselines, and evaluates them once on the frozen HRT template feature file:

`experiments/learned_baseline_hrt_template_features.csv`

No HRT template is used for model fitting or hyperparameter selection.

| Statistical/evaluation code | `evaluation/` and `runtime_validation/evaluate_*.py` |

## Important interpretation boundary

Sock Shop and Online Boutique are benchmark applications, not customer-production datasets. Their runtime evidence is generated by controlled, pre-specified interventions. Resource scaling is treated as a resource-footprint proxy where direct monetary cost is unavailable; the code does not invent cloud-billing evidence.

## Provenance

The main branch contains the finalized AAF prospective arbitration implementation. The pre-resubmission main branch has been preserved as `archive/pre-paper-2026-main`. Historical experiment branches remain available because they preserve the exact code state used for individual frozen experiments.

For manuscript verification, prefer the pinned commits/workflows documented here rather than rerunning against the latest upstream benchmark versions.
